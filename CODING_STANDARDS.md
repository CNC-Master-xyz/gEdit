# Coding standards for review

This file is read by the agents that review a change, not by the ones that write it. It holds the judgement rules a review checks against, beyond what the type check and the tests catch. Terms are those of [GLOSSARY.md](GLOSSARY.md).

## NC changes

Applies to every new or changed **code-data member**, **data mark** (a flag an entry of the code data carries; not the glossary's wait **Mark**) and **tracker or interpreter state** (what the modal interpreter or a script's tracker remembers from block to block).

1. **Every reader is listed.** The change names every reader that consumes the same entries, found by searching for the member or mark, not from memory. A reader nobody listed is where it breaks.
   - In the scripts: for example `motion_entry`, `pass_entry`, `refusals_of`, `place()`, and the other scripts that read the same code data.
   - In TypeScript: the loader, the inspector, the motion colours, and the other consumers of the same profile or code entries.
2. **Every reader has a probe.** Each listed reader has a test (or, where a test cannot reach it, a probe whose output is shown) that fails without the change. A test on the one reader the author had in mind does not count for the others. The two regressions of the v1.2.0 NC round were a mark that an unexpected reader read.
3. **Parity.** Where a rule has a TypeScript twin and a Python twin, both sides change and both are tested.

## Refuse rather than guess

- A refusal or a warning is preferred over a silent change. When the program is not understood (an unknown code, a cycle that is not reviewed, a frame that cannot be followed), the script refuses or reports; it does not guess.
- Refusals are all-or-nothing: a script that cannot change a block correctly leaves the whole document unchanged and says why, rather than changing the rest and skipping that block quietly.
- A new warning gets a reason name the Results rows and the tests can compare, and plain text for the NC programmer.

## Tests

- Every fix has a regression test that fails without it. Review confirms this by running the test against the code before the change.
- A golden is regenerated by the script that makes it and checked by eye against its criterion; a golden that is edited by hand to make a test pass is a finding.

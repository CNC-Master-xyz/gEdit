# v1.2.0: the finish plan

Written 2026-10-30, after Wave Y was pushed to `main` (`1179e748`). This page replaces the order of work in TODO.md item 6. Every open item of TODO.md and of the roadmap backlog is in exactly one of the four parts below.

## The line

- **v1.2.0 is what is on `main` now, plus the owner's answers of 2026-10-30 (branch `y/parked`).** No other work goes into v1.2.0.
- The only change allowed after that comes from the owner's test (part B). It is fixed before the tag only when it is a **blocker**: a crash, lost work, a file saved wrong, or NC output that is silently wrong. Everything else the test finds goes into part D.
- **Nothing that needs a machine holds the tag.** The owner has no machines of their own (2026-10-08). Machine facts stay marked "verify" in the app, and content not yet reviewed stays marked "review pending". Part C lists them.

## A. The session (finite)

1. **Land the owner's answers.** Gate `y/parked`, run it on GitHub (CI and harness), then add it to `main` as one commit.
2. **Tidy the records.** Tick the TODO items that are done but still open: Wave X, Wave Y, the Brand batch, the pre-wave step, and the P4a and P4e backlog lists, whose items are all ticked. Point TODO item 6 to this page.
3. **Version 1.2.0.** Bump the version on `main` and date the `CHANGELOG.md` entry, so that the version tested is the version tagged (T046).
4. **The test build.** Run the Release workflow by hand on `main` (a dry run). It builds the macOS, Windows and Linux bundles as downloads without making a release. The owner tests these (part B).
5. **Screenshots** for the user guide, retaken once on that build (T051).
6. **Blockers from the test**, if any: fix, then a new test build of the affected platform only.

## B. The owner's test of v1.2.0 (holds the tag)

Use the test build of A4 and the sample programs in `tests/fixtures/exit/`. Each row is something to see in the app, not on a machine. Write down what is wrong, with the file and the line.

**Install and basics, on macOS, Windows and Linux** (from [the release checklist](../releases/checklist.md)):
- [ ] The download matches `SHA256SUMS`; the app installs and starts (macOS: Open Anyway; Linux: `gedit-nc` and the menu entry, GNOME's `gedit` untouched).
- [ ] A Fanuc and a Klartext program open in tabs, the dialect in the status bar is right, the program map is filled.
- [ ] Edit, undo, redo; save a file without an edit, and its hash is unchanged.
- [ ] Close the window with a changed tab: gEdit asks; Cancel keeps it, Discard closes.
- [ ] A script with Python (Tool list) shows its table; without Python the script commands are off with a message, the rest works.
- [ ] About shows 1.2.0.

**What v1.2.0 adds, on one platform** (macOS is enough; the plan's §10 in short):
- [ ] Translate, Rotate and Mirror on a copy of a program: the result reads right, and a program they cannot handle is refused with a reason.
- [ ] Expand a drilling cycle; the time estimate per tool.
- [ ] Auto-space and auto-number while typing; print to PDF.
- [ ] Renumber a program with `M98 P… Q…` and `M99 P`.
- [ ] Split view; a multi-channel program in Channels Side by Side; Merge Channels Back; save the channel files (named like `PART_1.MPF`).
- [ ] Compare two programs in the aligned view and merge one block.
- [ ] Find in Folder on a folder of programs: results stream in, Stop stops.
- [ ] Double-click an NC file with gEdit open and closed: it opens as a tab in the running window.
- [ ] A key of your own on the keyboard page; Export Configuration, then Import it again.
- [ ] A user profile made with the profile form, with a colour of its own (the preview shows it); a machine with the Numbers table filled in.

**Windows only:**
- [ ] A key with AltGr (Swiss German) still types its AltGr character.
- [ ] A program on a mapped or `subst` drive set as a machine's folder opens with that machine.

When B is done and no blocker is open, the owner tags `v1.2.0`, checks the draft release and publishes it (T047).
